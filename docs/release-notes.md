# LiteView v1.6.0 — 无边框看图，锁定缩放对所有图生效

看图、简单编辑和打码，放在一个离线小工具里。本版新增无边框模式：窗口就是图片的大小，四周不露背景。「锁定缩放」改为对所有图生效，右键菜单把同类的收进了子菜单。打印、编辑和打码与 1.5.1 相同；设置、独立安装版和绿色版的使用方式不变。

## 本版更新

- **无边框模式**（Windows）：按 Ctrl+B，或在右键菜单「窗口 → 无边框」打开，再按一次回来，下次打开还是这样。
  - 去掉标题栏，窗口就是图片的大小。滚轮缩放时窗口跟着变，鼠标指着的点不动；换图时窗口变成新图的大小，最大到屏幕的九成。图片比屏幕大时窗口最大到整块屏，再放大就在里面拖着看。
  - 拖图片移动窗口；放大到能平移时拖是平移，按住 Shift 拖总是移动窗口。拖边缘、四个角改大小，保持图片的比例。
  - 鼠标移到顶部出现细标题栏：拖它移动，双击最大化，右边是最小化、最大化、关闭。
  - 按 E 进编辑时临时恢复标题栏，退出后回到无边框，窗口大小不变。
- **工具栏放不下时放到图片下面**（默认关）：无边框时窗口缩得比底部工具栏还窄，工具栏两头会被截断。在右键菜单「窗口」里打开这一项后，工具栏改在图片下面单独的一条里，按钮都能点，点它不抢图片窗口的焦点。这一条要多占约 20 MB 内存、18 MB 显存，所以默认不开。
- **窗口置顶**：右键菜单「窗口 → 窗口置顶」。
- **锁定缩放对所有图生效**：以前只在切到同样尺寸的图时保持缩放，别的尺寸照样重新适应窗口。现在切图时都保持缩放比例：同样尺寸的图连位置也保持，方便对比；尺寸不同时放在中间。
- **右键菜单更短**：旋转和翻转、文件（复制路径、重命名、在资源管理器中显示、打开方式、设为桌面背景）、窗口（无边框、置顶）各收进一个子菜单，鼠标指上去才出来。第一层从二十项减到十一项，窗口矮时也少滚动。

## 验证与发布门禁

每个发布提交都必须通过 Rust release 单元测试、全 targets Clippy、构建和 Python 打包测试。

无边框在两块屏（3840×2160 和 2560×1600）上用真鼠标、真滚轮、真键盘测：
- **窗口包着图片**，7 项全部通过。测试图带红边，「铺满」指窗口四条边内侧都是红边：打开时铺满；滚轮缩小时窗口中心不动；放大时鼠标在窗口里的相对位置不变；缩到最小窗口就停；拖边保持比例；换图跟着变；长图 100% 时拖是平移、Shift + 拖移动窗口。
- **无边框**，10 项全部通过：没有边框；拖图片移动；拖边、拖角保持比例；细标题栏出现和消失；双击最大化、还原；Ctrl+B / F11 / E / Esc；拖到另一块屏；点关闭。
- **工具栏放到图片下面**（打开这一项时）：
  - 只在窗口比工具栏窄时出现；
  - 按钮间距与窗口里的一样；
  - 按钮能点，不抢图片窗口的焦点，鼠标移开后收起；
  - 关掉无边框后小窗口放掉，内存 88.5 → 78.1 MB。
- **右键菜单**的三个子菜单都是鼠标指上去就出来，点「窗口 → 无边框」生效并存进设置。

私有桌面整轮回归 13 项：
- 看图交互、右键菜单两项按变短的菜单改了预期后通过：只有 520×360 的窗口还要滚动。
- 两项帧数没过，原因是这次显示器从 60 Hz 换成了 160 Hz。同样环境下实测 1.5.1 和 1.6.0 一样：拖动后 42 帧、80 帧/秒。
- 其余 9 项通过。

标签工作流要求 Windows x64、Linux x64、macOS arm64 / x64 全部通过构建门禁，以及一次性 Windows runner 的普通安装包和 MSIX 生命周期回归后才创建正式 Release。MSIX 测试证书仅用于隔离 runner 中的测试副本，不是商业签名。自动测试不替代人工界面验收或商店审核。

## 下载与运行

- Windows 10 / 11 x64：也可从 Microsoft Store 安装（商店更新需微软审核后推送）。`windows-x64.zip` 为绿色版，解压后运行 `LiteView.exe`；`windows-x64-setup.exe` 为当前用户安装包，不需要管理员权限。
- Linux x64：解压 `linux-x64.tar.gz` 后运行 `./LiteView`，构建基线为 Ubuntu 22.04。
- macOS：按机器选择 `macos-arm64.tar.gz`（Apple Silicon）或 `macos-x64.tar.gz`（Intel），将 `LiteView.app` 拖入 Applications。
- 发布包附 `SHA256SUMS.txt`、安装说明和第三方许可证。绿色版通过 `LiteView.portable` 标记将配置保存在程序旁的 `config` 目录。

## 已知限制

- 无边框只在 Windows 上；macOS / Linux 保留系统标题栏，菜单里没有「无边框」。
- 无边框时比最小窗口（约 160 × 100 点）还小的图，周围仍有背景。
- 「工具栏放到图片下面」时，比例弹出菜单里的输入框可能打不了字（这个小窗口不抢焦点），预设的比例可以点。
- 装了 PowerToys FancyZones 时，按住 Shift 拖窗口会贴进它的区域，这是 FancyZones 的功能。
- 在缩放不同的两块屏之间拖无边框窗口这一版没实测（与有标题栏时用同一个系统移动循环）。
- 跨屏拖动的修正只在 Windows 11 上；Windows 10 与 1.5.0 相同，没有在 Windows 10 上测过。
- 商店版更新后，资源管理器若还显示旧的「LiteView 图片」，重启资源管理器或重新登录一次后再看。
- 涂抹的笔触总是横的：用画笔斜着涂时，纹理也是横的，不跟着拖的方向走。
- 在设置里把默认打码效果选成「涂抹」后，如果再换回 1.4.0 或更早的版本，旧版不认识这个值，会把全部设置恢复成默认。
- 连续翻页的间隔（0.5 秒后开始、每张 0.3 秒）目前不能在设置里调。
- 右键菜单画在窗口里，不能超出窗口；窗口比菜单矮时要滚动。
- 打印目前只在 PDF 虚拟打印机上验证过；实体打印机的实际边距、份数、脱机与出错提示还没有在真机上验收，遇到问题欢迎反馈。macOS / Linux 暂不提供打印。
- 「交给打印机」表示已进入 Windows 打印队列，不代表纸已经印完；脱机或缺纸等状态由 Windows 和打印机报告。
- 打开 4800 万像素这样的大照片时，解码过程中内存会短暂升到 300 MB 以上；放大到 100%、编辑、复制、另存为或打印时要留原图（1200 万像素约多 60 MB），之后放掉。
- 软件渲染（没有可用显卡时）在 4K 屏上拖动、缩放时 CPU 占用明显更高。
- 显卡驱动在首次启动时直接崩溃的情况，第一次仍会出现“已停止工作”，再次启动才会自动改用软件渲染；卡住的旧进程不会被自动结束。
- 预算检查不是进程内存硬上限：SVG 解析/滤镜、系统解码器和并行预读仍有独立开销；进程级隔离和完整中途取消尚未实现。
- SVG 仍固定以 2048 px 栅格化，尚未随视口与缩放重绘。
- 真实 HEIC EXIF 方向及系统扩展组合、Linux/macOS 原生交互与桌面集成、屏幕阅读器和参考机性能验收仍未完成。
- 未进行 Windows 数字签名或 macOS 公证。请核对下载来源和校验值，不要关闭系统安全功能来绕过警告。
- Windows 默认应用仍需用户在系统设置中确认，不能保证所有图片格式一键设为默认。
