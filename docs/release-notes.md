# LiteView v1.7.1 — 文本框好拉了，写好的文字还能再拖

看图、简单编辑和打码，放在一个离线小工具里。本版修文字工具的两个问题：文本框很难拉宽、拉宽后字不跟着重排；写进图里的文字再也不能动。现在框的两侧整条边都能拉，写好的文字没被盖过时还能拿起来接着拖、接着改。还修了长提示被挤成一竖条。设置、独立安装版和绿色版的使用方式不变。

## 本版更新

- **文本框好拉了**：以前只有右边中间一个 7 像素的小点能拉宽，右边其余地方按下去是整个框移动，再往外一点就是确认（字变成像素），鼠标指针也一直是输入光标，看不出哪里能拉。现在框的左右两条边（连同四个角）往外 12 像素都能拉宽，拉左边时右边不动；上下边按住是拖动；两边都画了控制点，指针在左右边是左右箭头、在上下边是移动。
- **拉宽后字跟着重排**：以前拉宽文本框，框变大了，字还按放下时的宽度换行，确认后写进图里的也是旧的换行；拉窄再拉宽会停在拉窄时的宽度；放大看图时也一样。现在按框的宽度换行，放大、缩小看图时换行不变。
- **写好的文字能再拿起来**：用文字工具点已经写进图里的文字（指针是移动，停在上面画出它的框），那块恢复成写之前的样子，变回文本框，字体、字号、颜色回到属性栏，可以接着拖、改字、拉宽。放下时与拿起算一步，按一次 Ctrl+Z 回到原处；拿起后按 Ctrl+Z 是放回原处。写上去之后那块又画过一笔、打过码等，就拿不起来了（拿起会把后来的改动一起抹掉），点那里是放新的文本框。只有写了字（或背景）的地方算这段文字，旁边的空白处点下去照样放新文本框。
- **长提示不再挤成一竖条**：先出过一条短提示（如「已复制」），后面长的提示（如无边框的说明）以前挤成一竖条，每行一两个字。现在文字变了就重新量大小。

## 验证与发布门禁

每个发布提交都必须通过 Rust release 单元测试、全 targets Clippy、构建和 Python 打包测试。

在私有桌面上回放（独立配置，不动真鼠标）放文本框、打一句 48 个字母的话，再拉、拖，1.7.0 与本版各跑一遍：
- **拉宽 300**：本版 4 行变 1 行，确认后写进图里的也是 1 行；1.7.0 还是 4 行，写进图里也是 4 行。
- **拉窄再拉回原宽度**：本版 6 行回到 4 行；1.7.0 停在 6 行。
- **抓右边靠下往右拉 150**：本版拉宽（3 行变 2 行）；1.7.0 是整个框移过去。
- **抓左边往左拉 60**：本版左边动、右边不动。抓上边拖动整个框：两版都正常。
- **确认后按住文字往右下拖**：本版原处的深色像素 0、新位置与原来一样多；1.7.0 字留在原处不动，按下的地方多了一个空文本框。

单元测试：两侧整条边拉宽、上下边拖动；写好的文字拿起、拖动、放下后撤销一次回到原处，拿起后撤销放回原处，被盖过后拿不起来；只有改了的像素算能点到的范围。长提示：先显示 1 个字的提示，再显示 20 来个字的，大小从 41 × 344 变为 322 × 29（只用单元测试验证，没在真窗口里看）。发布前用户在自己电脑上装了修好的版本试过，没有问题。

私有桌面整轮回归 13 项里 11 项通过；两项帧数没过，数值与 1.7.0 相同（这台机器的主屏是 160 Hz，1.6.0 起同样环境下都是这个值）。

## 下载与运行

- Windows 10 / 11 x64：也可从 Microsoft Store 安装（商店更新需微软审核后推送）。`windows-x64.zip` 为绿色版，解压后运行 `LiteView.exe`；`windows-x64-setup.exe` 为当前用户安装包，不需要管理员权限。
- Linux x64：解压 `linux-x64.tar.gz` 后运行 `./LiteView`，构建基线为 Ubuntu 22.04。
- macOS：按机器选择 `macos-arm64.tar.gz`（Apple Silicon）或 `macos-x64.tar.gz`（Intel），将 `LiteView.app` 拖入 Applications。
- 发布包附 `SHA256SUMS.txt`、安装说明和第三方许可证。绿色版通过 `LiteView.portable` 标记将配置保存在程序旁的 `config` 目录。

## 已知限制

- 写好的文字只在这一次编辑里能再拿起来，退出编辑后就是普通的像素。拿起时属性栏换成这段文字的样式，之后新放的文字也用这个样式。记着的文字像素最多 64 MB（字很大、很多时，最早的先拿不起来）。
- WebM 只在 Windows 上能打开（macOS / Linux 显示「不支持的格式」），不放声音，超过 64 MB 的不打开。
- 16 位 TIFF、HDR / EXR 解码时还要多占内存：TIFF 解码器先解到它自己的缓冲区，整个文件也在内存里。
- 打开 4800 万像素这样的大照片时，解码过程中内存会短暂升到约 300 MB；放大到 100%、编辑、复制、另存为或打印时要留原图（1200 万像素约多 60 MB），之后放掉。
- 无边框只在 Windows 上；macOS / Linux 保留系统标题栏，菜单里没有「无边框」。
- 无边框时比最小窗口（约 160 × 100 点）还小的图，周围仍有背景。
- 在缩放不同的两块屏之间拖无边框窗口时，1:1 的小图在拖的途中窗口先按系统给的大小（多出一圈背景或裁掉一点），松开后变回包着图片。
- 装了 PowerToys FancyZones 时，按住 Shift 拖窗口会贴进它的区域，这是 FancyZones 的功能。
- 跨屏拖动的修正只在 Windows 11 上；Windows 10 与 1.5.0 相同，没有在 Windows 10 上测过。
- 商店版更新后，资源管理器若还显示旧的「LiteView 图片」，重启资源管理器或重新登录一次后再看。
- 在设置里把默认打码效果选成「涂抹」后，如果再换回 1.4.0 或更早的版本，旧版不认识这个值，会把全部设置恢复成默认。
- 连续翻页的间隔（0.5 秒后开始、每张 0.3 秒）目前不能在设置里调。
- 右键菜单画在窗口里，不能超出窗口；窗口比菜单矮时要滚动。
- 打印目前只在 PDF 虚拟打印机上验证过；实体打印机的实际边距、份数、脱机与出错提示还没有在真机上验收，遇到问题欢迎反馈。macOS / Linux 暂不提供打印。
- 「交给打印机」表示已进入 Windows 打印队列，不代表纸已经印完；脱机或缺纸等状态由 Windows 和打印机报告。
