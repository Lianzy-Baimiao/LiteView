# LiteView v1.6.1 — 打开、缩小大图时少占内存

看图、简单编辑和打码，放在一个离线小工具里。本版减少了打开和缩小大图时占的内存：常见的 JPEG、PNG 解码时不再同时留两份像素，解码也快了约三成；从 100% 缩小时一条条算。4800 万像素的照片翻图时内存最高约 370 → 300 MB，从 100% 缩小一点时约 620 → 450 MB。界面和功能与 1.6.0 相同；设置、独立安装版和绿色版的使用方式不变。

## 本版更新

- **打开大图少占内存、解码更快**：8 位的灰度、RGB、RGBA 图（大多数 JPEG、PNG，以及 RAW 里的预览图）直接解到最后的缓冲区里，原地展开成 RGBA。以前原始像素和转换后的像素同时在内存里。解码这一步：1200 万像素 +80 → +48 MB、54 → 37 ms；4800 万像素 +321 → +192 MB、243 → 173 ms。上下翻转、左右翻转、转 180° 的照片也原地转。
- **从 100% 缩小大图少占内存**：缩放停下后和适应窗口时的准确缩小改为一条条算、直接写进结果。以前三十多条同时算，再拼接、再转换，各多一份结果：4800 万像素缩到九成时这一步 +479 → +18 MB，1200 万像素 +102 → +9 MB。在后台线程里慢了 3 ~ 60 ms。
- 整个程序在本机测（4800 万像素）：从 100% 缩小一点时，专用工作集（任务管理器里的「内存」）最高 616 → 450 MB，提交峰值 877 → 715 MB；翻文件夹时专用工作集最高 370 → 295 MB。只打开一张、适应窗口时提交峰值 380 → 341 MB，专用工作集最高都是 275 MB。空闲、适应窗口、停在 100% 后稳定下来的值与 1.6.0 相同。

## 验证与发布门禁

每个发布提交都必须通过 Rust release 单元测试、全 targets Clippy、构建和 Python 打包测试。新测试逐字节核对：灰度、灰度 + 透明、RGB、RGBA 在每种原地翻转下与以前的转换结果相同；整张 PNG 解码结果相同；一条条缩小与整张一次算的结果相同（预乘透明度的字节和给显卡的像素两种写法）。内存用 `examples/decode_peak.rs` 在单独的进程里一次只做一次解码或缩小来量。

- 开着预读翻 4800 万像素的文件夹时，提交峰值反而高了 44 MB（476 → 520），专用工作集是降的；关掉预读时提交峰值 407 → 340。原因（发布后查清）：第一张图从原图换回缩略图的那一帧里，下一张已经开始解码，两张大图的像素同时在内存里；本版解码一开始就分配整块 RGBA（以前先是 RGB），叠出来更高。
- 私有桌面整轮回归 13 项里 11 项通过。两项帧数没过，原因与 1.6.0 相同：这台机器的显示器是 160 Hz，同样环境下 1.6.0 的值一样。

标签工作流要求 Windows x64、Linux x64、macOS arm64 / x64 全部通过构建门禁，以及一次性 Windows runner 的普通安装包和 MSIX 生命周期回归后才创建正式 Release。MSIX 测试证书仅用于隔离 runner 中的测试副本，不是商业签名。自动测试不替代人工界面验收或商店审核。

## 下载与运行

- Windows 10 / 11 x64：也可从 Microsoft Store 安装（商店更新需微软审核后推送）。`windows-x64.zip` 为绿色版，解压后运行 `LiteView.exe`；`windows-x64-setup.exe` 为当前用户安装包，不需要管理员权限。
- Linux x64：解压 `linux-x64.tar.gz` 后运行 `./LiteView`，构建基线为 Ubuntu 22.04。
- macOS：按机器选择 `macos-arm64.tar.gz`（Apple Silicon）或 `macos-x64.tar.gz`（Intel），将 `LiteView.app` 拖入 Applications。
- 发布包附 `SHA256SUMS.txt`、安装说明和第三方许可证。绿色版通过 `LiteView.portable` 标记将配置保存在程序旁的 `config` 目录。

## 已知限制

- 竖拍时没有转正像素、只在 EXIF 里记了要转 90° 的照片（不少手机这样存），以及 16 位、HDR 图，解码时还和以前一样多占一份。
- 打开 4800 万像素这样的大照片时，解码过程中内存会短暂升到约 300 MB；放大到 100%、编辑、复制、另存为或打印时要留原图（1200 万像素约多 60 MB），之后放掉。
- 无边框只在 Windows 上；macOS / Linux 保留系统标题栏，菜单里没有「无边框」。
- 无边框时比最小窗口（约 160 × 100 点）还小的图，周围仍有背景。
- 「工具栏放到图片下面」时，比例弹出菜单里的输入框可能打不了字（这个小窗口不抢焦点），预设的比例可以点。
- 装了 PowerToys FancyZones 时，按住 Shift 拖窗口会贴进它的区域，这是 FancyZones 的功能。
- 在缩放不同的两块屏之间拖无边框窗口还没实测（与有标题栏时用同一个系统移动循环）。
- 跨屏拖动的修正只在 Windows 11 上；Windows 10 与 1.5.0 相同，没有在 Windows 10 上测过。
- 商店版更新后，资源管理器若还显示旧的「LiteView 图片」，重启资源管理器或重新登录一次后再看。
- 涂抹的笔触总是横的：用画笔斜着涂时，纹理也是横的，不跟着拖的方向走。
- 在设置里把默认打码效果选成「涂抹」后，如果再换回 1.4.0 或更早的版本，旧版不认识这个值，会把全部设置恢复成默认。
- 连续翻页的间隔（0.5 秒后开始、每张 0.3 秒）目前不能在设置里调。
- 右键菜单画在窗口里，不能超出窗口；窗口比菜单矮时要滚动。
- 打印目前只在 PDF 虚拟打印机上验证过；实体打印机的实际边距、份数、脱机与出错提示还没有在真机上验收，遇到问题欢迎反馈。macOS / Linux 暂不提供打印。
- 「交给打印机」表示已进入 Windows 打印队列，不代表纸已经印完；脱机或缺纸等状态由 Windows 和打印机报告。
