# LiteView v1.1.0 — 启动问题修复

看图、简单编辑和打码，放在一个离线小工具里。本版主要修复部分 Windows 电脑上“点了没反应 / 打开图片没有反应 / 无法启动”的问题，建议所有 1.0.0 用户更新。设置、独立安装版和绿色版的使用方式不变。

## 本版更新

- **修复启动无反应**：1.0.0 的窗口在画出第一帧后才显示，之前显卡接口初始化出错、显卡驱动或叠加软件（录屏、游戏加速、性能监控等）崩溃或卡住，用户都看不到任何窗口或提示。现在：
  - Vulkan 窗口表面、设备或交换链初始化失败时，在同一次启动里自动改用 DirectX 12，再不行改用 OpenGL。默认仍首选 Vulkan。
  - 驱动或叠加软件导致崩溃、卡住时，下次启动自动跳过出问题的图形接口。
  - 一个窗口卡在启动中时，再双击图片不会被转给卡住的窗口，而是等待片刻后用其他接口打开。
  - 所有图形接口都失败时显示错误提示，说明原因和记录位置，不再毫无反应。
- **字体兼容**：系统的微软雅黑被替换成不兼容的字体文件时不再退出，改用可用字体。
- **反馈更容易**：“设置 → 关于”显示当前图形接口、已跳过的接口和上次遇到的问题（含出错模块），截图即可反馈，不需要运行命令。相关记录只保存在本机，不会上传，见隐私政策。
- **HEIF 提示更准确**：VVC 编码的 HEIF、只有图像序列的 HEIF/AVIF 现在提示“不支持这种格式”，不再误报“文件已损坏”；真正截断或损坏的 HEIC 仍提示已损坏。

## 验证与发布门禁

每个发布提交都必须通过 Rust release 单元测试、全 targets Clippy、构建和 Python 打包测试。本版新增的启动保护经过故障注入验证：在 1.0.0 上可复现的表面不受支持、建设备失败、交换链失败、驱动崩溃、驱动卡住和字体替换等场景，新版本都能自动恢复或给出提示。Windows CI 与发布流程在私有桌面实际启动正式 EXE，以首帧与截图判定，并覆盖缺少 DLL、缺少 Vulkan 加载器的对照。

标签工作流要求 Windows x64、Linux x64、macOS arm64 / x64 全部通过构建门禁，以及一次性 Windows runner 的普通安装包和 MSIX 生命周期回归后才创建正式 Release。MSIX 测试证书仅用于隔离 runner 中的测试副本，不是商业签名。自动测试不替代人工界面验收或商店审核。

## 下载与运行

- Windows 10 / 11 x64：也可从 Microsoft Store 安装（商店更新需微软审核后推送）。`windows-x64.zip` 为绿色版，解压后运行 `LiteView.exe`；`windows-x64-setup.exe` 为当前用户安装包，不需要管理员权限。
- Linux x64：解压 `linux-x64.tar.gz` 后运行 `./LiteView`，构建基线为 Ubuntu 22.04。
- macOS：按机器选择 `macos-arm64.tar.gz`（Apple Silicon）或 `macos-x64.tar.gz`（Intel），将 `LiteView.app` 拖入 Applications。
- 发布包附 `SHA256SUMS.txt`、安装说明和第三方许可证。绿色版通过 `LiteView.portable` 标记将配置保存在程序旁的 `config` 目录。

## 已知限制

- 显卡驱动在首次启动时直接崩溃的情况，第一次仍会出现“已停止工作”，再次启动才会自动换接口；卡住的旧进程不会被自动结束。
- 预算检查不是进程内存硬上限：SVG 解析/滤镜、系统解码器、GPU 和并行预读仍有独立开销；进程级隔离和完整中途取消尚未实现。
- SVG 仍固定以 2048 px 栅格化，尚未随视口与缩放重绘。
- 真实 HEIC EXIF 方向及系统扩展组合、Linux/macOS 原生交互与桌面集成、屏幕阅读器和参考机性能验收仍未完成。
- 未进行 Windows 数字签名或 macOS 公证。请核对下载来源和校验值，不要关闭系统安全功能来绕过警告。
- Windows 默认应用仍需用户在系统设置中确认，不能保证所有图片格式一键设为默认；混合 DPI、多屏和其他字体环境仍需原生验收。
