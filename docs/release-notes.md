# LiteView v1.7.0 — 打开 WebM 表情包，SVG 放大不发虚，涂抹顺着拖的方向

看图、简单编辑和打码，放在一个离线小工具里。本版在 Windows 上能打开 WebM 表情包（Telegram 那样带透明的 VP9 动图）；SVG 放大超过 1:1 不再发虚；涂抹画笔顺着拖的方向走。还修了比例菜单的输入框打不了字、无边框窗口在缩放不同的两块屏之间来回后变小，竖拍照片和 16 位图解码更快、更省内存。设置、独立安装版和绿色版的使用方式不变。

## 本版更新

- **打开 WebM 表情包**（Windows）：用系统的「VP9 视频扩展」解码（Windows 11 一般自带），颜色和透明通道分别解码再合起来，循环播放，透明的地方显示棋盘格；没装扩展时提示去微软商店装。翻文件夹、打开对话框、拖进窗口都认 .webm。超过 64 MB 的当视频，不打开；声音不放。商店版装上本版后，资源管理器「打开方式」里能选 LiteView（不改默认应用）；独立版在「设置 → 文件关联 → 专业」里勾上 webm。
- **SVG 放大不发虚**：SVG 按长边 2048 像素画好显示，以前放大超过 1:1 就是把这张图拉伸。现在缩放、平移停下约 0.12 秒后，在后台按屏幕的像素重画看得见的那块，1:1 叠在上面。只画看得见的那块，多占的显存与窗口大小有关，与放大倍数无关。编辑、打印、复制、另存为还是用长边 2048 的那张。
- **涂抹顺着拖的方向走**：以前画笔斜着、竖着拖，笔触也是横的。现在拖出半个笔头宽后按这一段的方向定下走向（来回一样，离水平不到 4° 的算横的），开头先横着涂的那一小块按新走向重算。框选还是横的。和以前一样只留每段的平均色，原图的细节一点不留。
- **比例菜单的输入框能打字了**：点工具栏上的比例（如「37%」）打开菜单，以前一点里面的输入框菜单就关了，打的字变成快捷键（方向键翻页）。现在点外面、回车、选预设才关；打开时光标已经在输入框里、现在的比例已经选中，直接打字回车。「工具栏放到图片下面」时也一样，打完后按键回到图片窗口。
- **无边框窗口换屏不变小**：在缩放不同的两块屏之间拖无边框窗口，按 1:1 显示的小图以前来回一次窗口小一圈（回来后是 83%）。现在换屏时按逻辑大小不变换算缩放（最多 100%），回来后还是 100%、和原来一样大。
- **竖拍照片、16 位图解码更快、更省内存**：只在 EXIF 里记了转 90° 的竖拍照片（很多手机、相机这样存）和 16 位的 PNG、TIFF 以前多占一份内存。4800 万像素竖拍 JPEG：300 → 185 ms，解码时多占的 +328 → +253 MB（和横着的一样）；不用转的 4800 万像素 JPEG：173 → 143 ms；16 位 PNG：+586 → +403 MB。
- **翻大图文件夹、编辑大图时少占内存**：开着预读翻 4800 万像素的文件夹，提交峰值 520 → 344 MB；编辑 4800 万像素的图、缩小显示时改整张（全选删除、撤销、翻转），专用工作集峰值约 1280 → 760 MB。

## 验证与发布门禁

每个发布提交都必须通过 Rust release 单元测试、全 targets Clippy、构建和 Python 打包测试。

在两块屏（3840×2160 125%、2560×1600 150%）上用真鼠标、真键盘测：
- **比例输入框**：点输入框、全选、打 15、→、回车：缩放变成 15%，→ 没有翻页，打完后图片窗口回到最前面；1.6.1 菜单关掉、→ 翻到下一张。
- **无边框跨屏**：拖图片、拖细标题栏，1:1 小图和适应屏幕的大图各来回一次，窗口跟着鼠标、落在目标屏上、包着图片；小图来回后还是 100%。窗口包着图片 7 项、无边框 10 项全部通过。
- **有标题栏的窗口跨屏**（抓标题栏左、中、右，最大化后拖下来，Win + Shift + 方向键）：每次过界只变一次，逻辑大小不变。

逐字节核对：竖拍、16 位图的新解法与以前的转换在 8 种方向、8 种像素格式下相同；原地转置与按下标搬相同；斜着涂抹分块算与整张算相同，同一格里的像素换位置结果不变；SVG 重画的一块与整张画的同一块对齐。WebM：自己生成的测试图（64 × 48、带透明、6 帧）与 ffmpeg 解出来的一样；用户给的 512 × 512、79 帧贴纸 131 ms 打开、正常播放。

私有桌面整轮回归 13 项里 11 项通过；两项帧数没过，原因与 1.6.0、1.6.1 相同（这台机器的主屏是 160 Hz，同样环境下数值一样；换到 60 Hz 屏时这两项也通过）。

标签工作流要求 Windows x64、Linux x64、macOS arm64 / x64 全部通过构建门禁，以及一次性 Windows runner 的普通安装包和 MSIX 生命周期回归后才创建正式 Release。MSIX 测试证书仅用于隔离 runner 中的测试副本，不是商业签名。自动测试不替代人工界面验收或商店审核。

## 下载与运行

- Windows 10 / 11 x64：也可从 Microsoft Store 安装（商店更新需微软审核后推送）。`windows-x64.zip` 为绿色版，解压后运行 `LiteView.exe`；`windows-x64-setup.exe` 为当前用户安装包，不需要管理员权限。
- Linux x64：解压 `linux-x64.tar.gz` 后运行 `./LiteView`，构建基线为 Ubuntu 22.04。
- macOS：按机器选择 `macos-arm64.tar.gz`（Apple Silicon）或 `macos-x64.tar.gz`（Intel），将 `LiteView.app` 拖入 Applications。
- 发布包附 `SHA256SUMS.txt`、安装说明和第三方许可证。绿色版通过 `LiteView.portable` 标记将配置保存在程序旁的 `config` 目录。

## 已知限制

- WebM 只在 Windows 上能打开（macOS / Linux 显示「不支持的格式」），不放声音，超过 64 MB 的不打开。
- 16 位 TIFF、HDR / EXR 解码时还要多占内存：TIFF 解码器先解到它自己的缓冲区，整个文件也在内存里。
- 打开 4800 万像素这样的大照片时，解码过程中内存会短暂升到约 300 MB；放大到 100%、编辑、复制、另存为或打印时要留原图（1200 万像素约多 60 MB），之后放掉。
- 无边框只在 Windows 上；macOS / Linux 保留系统标题栏，菜单里没有「无边框」。
- 无边框时比最小窗口（约 160 × 100 点）还小的图，周围仍有背景。
- 在缩放不同的两块屏之间拖无边框窗口时，1:1 的小图在拖的途中窗口先按系统给的大小（多出一圈背景或裁掉一点），松开后变回包着图片。
- 装了 PowerToys FancyZones 时，按住 Shift 拖窗口会贴进它的区域，这是 FancyZones 的功能。
- 跨屏拖动的修正只在 Windows 11 上；Windows 10 与 1.5.0 相同，没有在 Windows 10 上测过。
- 商店版更新后，资源管理器若还显示旧的「LiteView 图片」，重启资源管理器或重新登录一次后再看。
- 在设置里把默认打码效果选成「涂抹」后，如果再换回 1.4.0 或更早的版本，旧版不认识这个值，会把全部设置恢复成默认。
- 连续翻页的间隔（0.5 秒后开始、每张 0.3 秒）目前不能在设置里调。
- 右键菜单画在窗口里，不能超出窗口；窗口比菜单矮时要滚动。
- 打印目前只在 PDF 虚拟打印机上验证过；实体打印机的实际边距、份数、脱机与出错提示还没有在真机上验收，遇到问题欢迎反馈。macOS / Linux 暂不提供打印。
- 「交给打印机」表示已进入 Windows 打印队列，不代表纸已经印完；脱机或缺纸等状态由 Windows 和打印机报告。
