# 轻量内置打印方案

来源：[GitHub #1](https://github.com/Lianzy-Baimiao/LiteView/issues/1)，2026-10-19 提出；2026-10-20 核实仍为 Open。本文是实施方案，**打印功能尚未实现**。先处理启动崩溃，打印作为独立功能交付，不混进兼容性修复包。

## 2026-10-20 范围收敛

用户本地体验 FastStone 后认为其打印功能过重，包含边框、拼图等大量附加功能。本次仅记录本地待办，不开始实现，不代发 GitHub 回复，也不关闭 issue。

LiteView 只借鉴清晰的纸张预览，不照搬整套照片排版功能。目标是“看图顺手，顺便能打印”，不是点进打印后还要学习另一套软件。

## 目标

提供简单的单图纸张预览和必要的尺寸控制，保留 LiteView 轻巧、启动快的特点。不调用资源管理器的“打印图片”向导，不嵌入浏览器或整套文档渲染引擎，也不依赖 FastStone。

Windows 原生图片打印向导与打印机驱动不是一回事：排版及预览由 LiteView 控制，实际出纸仍通过 Windows 打印系统和用户安装的驱动。驱动的纸盒、双面和色彩等属性可通过打印机“属性”入口设置。

## 首版范围

- 看图菜单与 Ctrl+P 入口；无可用图片时禁用。打开自己的打印预览，不立即产生打印任务。
- 操作流程为 Ctrl+P → 看预览 → 打印；左侧纸张预览，右侧常用设置，不堆叠模板和排版工具。
- 单张图片、单页输出；动图打印当前帧并明确标记。编辑模式须使用当前合成结果，不能误打印磁盘里的旧图或尚未合并的原图。
- 选择打印机、设备支持的纸张、横向/纵向、份数；A4、Letter、照片纸仅在驱动支持时列出。
- 默认适合页面、保持比例、居中并完整打印，不自动裁切；需要具体大小时可填写毫米尺寸，边距收进“更多设置”。指定尺寸超出可打印区域时明确提示，不静默裁掉图片。
- 预览同时标出纸张边界和打印机不可打印区域。按设备可打印区域换算 DPI，避免边缘丢失、横竖颠倒或尺寸不一致。
- 透明区域合成到白纸；读取已有旋转结果，避免再应用 EXIF 方向而二次旋转。
- 点击“打印”才提交；显示提交中、已提交或失败。进入队列不等于纸张已实际打印完成。

首版明确不做：装饰边框、拼图、照片墙、多图联系表、证件照模板、海报分割、批量排版、页眉页脚和专色管理。填满纸张并裁切也不作为首版必需项。后续只有真实需求支持时才单独评估，不因为参考软件有就自动加入。

## 实现边界

- `print/layout`：无平台依赖的毫米/像素几何、适合页面/自定义尺寸计算、超出可打印区域的检测与硬件边距，供预览和输出共享。
- `print/document`：冻结用户点击打印时的图片/当前帧/编辑结果，异步任务不得随当前查看图片变化。
- `platform/windows/print`：惰性加载打印机信息与设备能力；管理打印上下文和任务生命周期，不在应用启动时访问打印服务。
- 打印机 I/O 放后台，窗口继续响应；失败和取消必须释放句柄，中止尚未完成的任务。不得把“用户取消”显示成程序崩溃。
- 无打印机或 Print Spooler 停止时给出普通提示，不能影响看图或软件启动。

## 验收

1. 几何单元测试：横竖图、极宽图、DPI 换算、非对称硬件边距、非法/非有限尺寸、透明合成、自定义尺寸越界；验证默认布局不会裁切图片。
2. 相同参数的预览与输出使用同一布局结果，避免两套比例公式。
3. 在隔离 Windows 环境使用 Microsoft Print to PDF 验证纸张尺寸、方向、毫米定位与边距；检查输出文件，而不只检查 API 返回成功。
4. 真打印机验收覆盖取消、驱动属性、份数、脱机与失败提示；只有 PDF 测试时明确保留物理打印未验收的边界。
5. 对比启动时间和包大小；打印模块未使用时不枚举设备、不增加后台服务。
