- [x] 动图每帧画 2 ~ 3 次（2026-10-28 修好）：除了 egui 减去 predicted_dt 提前醒，还有一个原因——帧里发出的重绘请求要等 Present 等完垂直同步才送到窗口循环，那时这一帧已经画过了，又排一帧。窗口循环改为按这一帧输出的 repaint_delay 排下一帧，只合并帧外（后台线程）的请求；动图把 predicted_dt 加回去，差 2 ms 以内也算到点。本机 60 Hz，私有桌面和真实桌面一样：30 / 40 / 20 ms 的 GIF 每次换帧画 1.0 次（以前 1.8 / 2.4 / 1.2），换帧间隔正好 30.0 / 40.0 / 20.0 ms（以前凑到 33 / 50 ms）；静止、拖动、缩放、提示、面板、按住翻页、菜单、打印、关窗口与 v1.5.0 一样（`dist/mem-20261023/gif_draws.py`、`fps_check.py`、`regress.sh`）。另：每次换帧都叫醒 16 个线程池线程、空转后才睡，一张 480×270 的 GIF 要占约三分之一个核；50 万像素以下改为单线程转换，放这张 GIF 时进程 CPU 从全机 1.2 ~ 2.2 % 降到 0.04 ~ 0.1 %
