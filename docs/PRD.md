# LiteView 轻量看图 · 产品需求文档（PRD）

> 开源（MIT）：https://github.com/Lianzy-Baimiao/LiteView 。产品名为暂定名（见 13）。最后更新：2026-10-17（文档 v0.3；应用为 v0.1.2 开发预览）

## 1. 背景

Windows 自带的「照片」启动慢、占内存，「画图」能改图但没有马赛克 / 模糊；第三方看图软件要么捆绑广告、后台常驻，要么界面老旧。日常最高频的需求其实很简单：双击秒开、翻看同文件夹、缩放看细节；偶尔改一下（裁剪、标注），以及把截图里的手机号、头像、聊天记录打码后再发出去。本项目用 Rust 写一个启动快、界面干净、自带「画图」级编辑和好用又安全的打码工具的看图软件。

## 2. 目标

1. **快**：双击图片立即出窗口、出图；切换下一张无等待；缩放、拖动跟手。
2. **全**：常见格式自带解码；系统装了解码扩展的格式（HEIC、RAW、JPEG XL 等）也能看；GIF / APNG / 动态 WebP 默认播放，可逐帧查看。
3. **轻**：单个可执行文件、免安装；无后台进程、无托盘、无广告；不联网。
4. **能改**：右键「编辑」，功能对齐 Windows 画图的常用部分；额外提供打码：马赛克 / 模糊，画笔涂抹（圆圈大小可调）或框选，用法和微信、QQ 截图的马赛克一样。
5. **好看**：现代扁平化界面，跟随系统深色 / 浅色，内容优先。
6. **开源、跨平台**：MIT 协议，代码在 GitHub；Rust 编写，Windows 优先，Linux、macOS 也能用。

## 3. 不做（v1）

- 图库管理：相册、标签、评分、人脸、云同步。
- 专业修图：图层、蒙版、滤镜调色、RAW 冲印、AI 抠图 / 生成式擦除、PS 式的涂抹 / 仿制图章。
- 动图编辑、打码（动图只看）。
- 视频播放；在线更新与统计。

## 4. 设计原则

- **简单**：功能和用法向「画图」、截图工具的马赛克看齐，不做专业软件那一套；每个功能只露出最常用的选项。
- **内容优先**：图片占满窗口，工具栏按需出现、不用时淡出；没有花哨的转场。
- **不打断**：解码、扫描文件夹、保存都在后台线程，界面不卡、不出现「未响应」；出错在界面内提示，不弹一串对话框。
- **改图不丢图**：覆盖原图前确认；保存先写临时文件再替换，失败时原图不变。
- **打码必须真的盖住**：保存后的文件里不能残留被盖住的原始像素（含 EXIF 缩略图、文件尾部残留，见 6.8.4）。
- **隐私**：不联网、不上传；不在磁盘留图片缓存（缩略图、预读只放内存）。

## 5. 目标用户与场景

| 用户 | 典型场景 |
|---|---|
| 普通用户 | 双击照片打开，方向键翻看整个文件夹，滚轮放大看细节，Del 删掉废片 |
| 办公 / 客服 / 运营 | 截图 → 打开（或 Ctrl+V 粘贴）→ 右键打码 → Ctrl+C 复制 → 粘贴到聊天窗口 |
| 设计 / 开发 | 看 PNG 透明通道、SVG、ICO 各尺寸；GIF 逐帧检查动画、导出某一帧 |
| 摄影爱好者 | 快速浏览 HEIC / RAW 预览，查看 EXIF，删掉废片 |

### 6.4 图片格式

「支持所有图片格式」的落地方式：常用格式用**自带解码器**（纯 Rust，各平台结果一致），其余格式交给系统的图像组件——Windows 的 **WIC**（系统或用户装了哪种解码扩展，就能看哪种）、macOS 的 ImageIO（P2）。识别格式看文件内容（文件头），不看扩展名（网上下载的图常有扩展名不对的）。

| 格式 | 查看 | 另存为 | 解码来源 | 优先级 |
|---|---|---|---|---|
| JPEG | ✔ | ✔ | 自带 | P0 |
| PNG / APNG | ✔（含动画） | ✔ | 自带 | P0 |
| GIF | ✔（含动画） | ✔（静态图） | 自带 | P0 |
| BMP / DIB | ✔ | ✔ | 自带 | P0 |
| WebP（含动画） | ✔ | ✔（无损 P0、有损 P1） | 自带 | P0 |
| ICO / CUR | ✔ | — | 自带 | P0 |
| TIFF（多页） | ✔ | ✔ | 自带 | P0 |
| SVG | ✔（目标：随缩放保持矢量清晰；当前固定长边 2048 px 栅格化，见 OPT-06） | — | 自带 | P1 |
| AVIF | ✔ | P2 | Windows 走 WIC（AV1 扩展）；是否自带解码器（各平台都能看）在 M0 评估 | P1 |
| HEIC / HEIF | ✔ | — | 只用系统组件：Windows WIC（P1）、macOS ImageIO（P2）；Linux 不支持（见下方说明） | P1 |
| JPEG XL | ✔ | — | 自带 | P1 |
| TGA / DDS / QOI / PNM / HDR / EXR / Farbfeld | ✔（HDR / EXR 色调映射后显示） | — | 自带 | P1 |
| PSD | ✔（显示合并后的图像） | — | 自带 | P2 |
| RAW（CR2 / CR3 / NEF / ARW / DNG / RAF / ORF / RW2 …） | ✔ 显示内嵌的 JPEG 预览（快，各平台都能看）；完整解码走 WIC（仅 Windows，P2） | — | 自带预览 + WIC | P1 |
| JPEG XR / 其它装了 WIC 解码器的格式 | ✔（仅 Windows） | — | WIC | P1 |

- **HEIC**：iPhone 照片用 HEVC 编码，HEVC 有专利授权问题，**不自带解码器**，只走系统组件。Windows 需要「HEIF 图像扩展」（免费）+「HEVC 视频扩展」（商店版收费，部分品牌机预装免费的厂商版），缺少时在错误页说明原因并提供直达微软商店的按钮；macOS 系统自带；Linux 暂不支持。
- **JPEG XL**：Windows 的系统扩展只支持 Win11 24H2 及以上，所以自带解码器（Win10、Linux、macOS 都能看）。
- **色彩**：正确处理 8 / 16 位、灰度、透明通道、CMYK JPEG；按内嵌 ICC 配置文件转到 sRGB（否则 iPhone 的 Display P3 照片会发灰）——P2。
- **安全上限**：单边不超过 65535、总像素不超过 10 亿；单张解码预算目标默认 4 GiB（可设），超出时提示「图片过大」而不是卡死。当前尚未贯穿所有解码/回退入口，也不等于进程总内存上限，补齐要求见 OPT-01。
- 另存为 GIF：已实现少色图精确保色、多色图 NeuQuant 量化与蛇形 Floyd–Steinberg 抖动；透明像素不参与调色板训练与误差扩散。GIF 只支持二值透明，当前 alpha = 0 为透明，其余为不透明，不承诺保留半透明。

### 6.6 文件关联与系统集成

Windows 10 / 11 不允许程序直接改「默认应用」（系统用 `UserChoice` 哈希保护）。正确做法：把本软件**注册**为可以打开这些格式的程序，再带用户去系统设置里选为默认。下表的注册、关联做法针对 Windows，macOS、Linux 见最后两行。

| 功能 | 要求 | 优先级 |
|---|---|---|
| 设置页 | 按常用 / 更多 / 专业 / RAW 分组；提供「常用格式」「全部格式」「清空选择」和只看所选待设置项。勾选只表示本次计划，不代表已设为默认 | P0 |
| 注册 | 只写当前用户（`HKCU`），不需要管理员权限：ProgID、`OpenWithProgids`、能力声明等；增量注册，不因取消勾选而删除已有 ProgID；写完通知资源管理器刷新 | P0 |
| 设为默认 | 「前往系统设置」先登记所选格式，再打开 Win11 本软件默认应用页；旧系统或启动链接失败时回退默认应用首页。用户按扩展名确认，不承诺图片格式能一键全部设为默认；启动失败提供手动路径 | P0 |
| 状态 | 使用系统关联查询接口判断实际默认处理程序，显示完成数量、待设置项；返回时刷新，页面可见时两秒轮询而非每帧读注册表 | P1 |
| 移除注册 | 二次确认后清理本软件的格式注册与右键菜单；不写 UserChoice、不自动恢复旧默认应用，操作前提示用户先选择替代应用 | P0 |
| 便携原则 | 用户不点「注册」就**不写注册表**（绿色版直接运行不留痕） | P0 |
| 资源管理器右键 | 图片右键「用 LiteView 编辑」「用 LiteView 打码」。经典菜单（Win11 在「显示更多选项」里）P1；Win11 新菜单第一层需要 COM 扩展 + 签名的稀疏包，P2 | P1 / P2 |
| 首次启动 | 询问一次「设为默认看图软件？」，可「以后再说」或「不再询问」 | P1 |
| 命令行 | `LiteView <文件>`、`--edit <文件>`、`--mosaic <文件>`、`--register` / `--unregister`（给安装程序用） | P0 |
| macOS | 程序包里声明支持的格式，出现在「打开方式」里；用户在「显示简介 → 打开方式 → 全部更改」设为默认 | P2 |
| Linux | 安装 `.desktop` 文件并声明 MIME 类型；「设为默认」用 `xdg-mime default` | P2 |

### 6.7 编辑（参照 Windows 画图）

#### 6.7.1 进入与退出

- 入口：右键「编辑」/「打码」、E 键、底部工具栏的编辑按钮、资源管理器右键、`--edit`。
- 在同一个窗口里切换：保持当前缩放与位置，顶部滑入编辑工具栏（150 ms），查看用的浮动工具栏隐藏。
- 动图不能编辑、打码（见 6.3）。
- 退出：「完成」（保存后回到查看）/「取消」；有未保存修改时询问「保存 / 不保存 / 取消」。图片来自剪贴板、且结果已经复制到剪贴板时不再询问（见 7.4）。编辑时 ← → 不切换图片，避免误操作丢修改。
- 内部统一按 8 位 RGBA 编辑；16 位 / HDR 图片进入编辑时提示「保存后为 8 位」。

| 画图（Win11）的功能 | 本软件 | 优先级 | 说明 |
|---|---|---|---|
| 矩形选择 | ✔ | P0 | 移动、复制、剪切、删除；Shift 约束为正方形 |

#### 6.7.3 文字与形状

- **文字**：点击放置文本框，可拖动、拉宽；支持中文输入法（候选窗跟随光标）、多行；属性栏：字体（列出系统字体）、字号、粗体 / 斜体 / 下划线 / 删除线、颜色、背景（透明 / 填辅色）。确认前可改，点框外或切换工具后变成像素，不能再改（与画图一致）。
- **形状**：画完后保留 8 个控制点，可拉伸、移动、改颜色和线宽，直到切换工具或点空白处。Shift：正方形 / 正圆 / 45° 角直线。箭头的箭头大小随线宽变化。
- 画笔、形状、文字默认抗锯齿（铅笔除外）。

#### 6.7.4 颜色

- 主色 / 辅色两个色块，X 交换；绘图工具左键用主色、右键用辅色（与画图一致）。
- 预设 20 色调色板（扁平风格配色，含黑白灰与常用标注色：红 `#E5484D`、橙、黄、绿、蓝 `#0A84FF`、紫 等）+ 最近用过的 10 个自定义色。
- 自定义颜色：色相 / 饱和度 / 亮度选取区、HEX 与 RGB 输入、透明度（P1）。

#### 6.7.5 撤销与右键

- Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z），至少 50 步。一笔、一个形状、一次框选打码各算一步。
- 历史按 256×256 分块只存改动过的块，总内存设上限（默认 512 MB），超出时丢弃最早的步骤。
- 编辑模式的右键：选择工具下、或在选区上，弹出「复制 / 剪切 / 粘贴 / 裁剪到选区 / 全选 / 删除 / 撤销」菜单；绘图工具下右键 = 用辅色画（与画图一致）。

### 6.8 打码（核心功能）

和微信、QQ 截图、Snipaste 的马赛克一样简单：选好效果，按住涂抹或者拖个框。

#### 6.8.1 用法

| 功能 | 要求 | 优先级 |
|---|---|---|
| 入口 | 编辑工具栏里单独一组的「打码」按钮（快捷键 M）；查看模式右键「打码」直接进入编辑并选中此工具 | P0 |
| 效果 | 马赛克（方块）/ 模糊，二选一 | P0 |
| 画笔 | 按住左键涂抹。光标是与实际大小一致的圆圈（随缩放变化，黑白双色描边，在任何背景上都看得见）；鼠标移动快时也连成一片，不出现断点 | P0 |
| 框选 | 拖出矩形，松开立即生效，可连续框多个；拖动中实时预览；拖动中按 Esc 取消这一框 | P0 |
| 圆圈大小 | 属性栏滑块，或 `[` `]` 每次减小 / 增大约 10%；按图片像素计，4 ~ 1000 px；调整时在画布中央短暂显示圆圈和数值 | P0 |
| 强度 | 属性栏滑块：马赛克 = 方块大小，模糊 = 模糊程度，都是 8 ~ 128 px。最低档也是 8 px，因为太小的马赛克能被工具还原出文字 | P0 |
| 默认值 | 按图片大小自动算，大图上也看得出效果。短边记为 S：方块 = max(8, S / 80)、模糊半径 = max(8, S / 60)、圆圈直径 = max(24, S / 20)。例：1920×1080 截图 → 方块 13、圆圈 54；4000×3000 照片 → 方块 37、圆圈 150。用户改过的值记住，下次沿用 | P0 |
| 撤销 | 一笔、一个框各算一步 | P0 |

要完全盖住（如证件号），用带填充的矩形形状即可，不单独做纯色打码。

#### 6.8.2 属性栏

```
+----------------------------------------------------------------------------+
| (*Brush)(Rect) | (*Mosaic)(Blur) | Size o----O------ 54px | Level --O-- 13 |
+----------------------------------------------------------------------------+
```

1. 方式：画笔 / 框选；效果：马赛克 / 模糊。都是分段按钮，点一下切换。
2. 大小：圆圈大小，只在画笔方式下显示。
3. 强度：马赛克的方块大小 / 模糊程度。

#### 6.8.3 效果细节

- **马赛克方块对齐整张图**（从左上角起划分）：不管在哪里涂、涂几次、画笔和框选混着用，方块位置都一致，不会出现错位的碎方块。
- **同一笔不越涂越重**：以落笔前的图像为准计算，同一笔反复涂同一处结果不变；新的一笔可以叠在旧的效果上。
- **流畅**：涂抹、拖框时实时预览，4K 图片保持 ≥ 30 帧；只重算改动的区域。

#### 6.8.4 打码安全（用户看不见，但必须做到）

| 要求 | 说明 | 优先级 |
|---|---|---|
| 效果写进像素 | 保存的文件里没有图层、没有原图备份 | P0 |
| 不残留文件尾部 | 覆盖保存先写临时文件、写完再替换原文件，绝不在原文件上覆盖写入。2023 年的 aCropalypse 漏洞（Google Pixel 截图编辑 CVE-2023-21036、Windows 截图工具 CVE-2023-28303）就是覆盖写入后没截断，旧图数据留在文件尾部，被人恢复出了裁掉的内容 | P0 |
| 去掉元数据 | 打过码的图，保存时默认去掉全部元数据：EXIF 缩略图（可能是打码前的原图）、GPS、相机信息等；「另存为」里可改。颜色配置文件（ICC）在支持的输出格式中保留；无法保留时必须说明能力边界与色彩处理方式（OPT-07 / OPT-11），不能承诺所有格式一直保留。没打码、只做了别的编辑时保留 EXIF，但缩略图、厂商私有数据（MakerNote，里面也可能有预览图）一律去掉，方向改为 1 | P0 |
| 不留痕 | 复制到剪贴板的是打码后的结果；撤销历史只在内存里，超出上限就丢弃，不写磁盘 | P0 |

## 7. 界面设计（现代扁平化）

### 7.1 风格

- **扁平**：用色块和留白分层次；不用渐变、拟物、立体按钮；分隔用 1 px 浅色线。
- **阴影**只给浮在内容上面的东西（菜单、浮动工具栏、弹出面板），淡而短；其它一律无阴影。
- **图标**：线性图标，1.5 px 线宽、圆角端点；工具栏 20 px、菜单 16 px。用 Fluent UI System Icons（MIT 许可，与 Windows 11 风格一致），编进程序里，不依赖系统图标字体。
- **标题栏**：用系统原生标题栏（保留贴靠布局、拖动、双击最大化等系统行为）；Win11 上颜色设成与看图背景一致，看起来与内容连成一体；其它系统用系统的深色 / 浅色标题栏。
- **材质**：一律纯色；Win11 的 Mica 半透明窗口背景之后再考虑（P2）。
- **动效**：只用来表达状态变化（淡入淡出、滑入），≤ 200 ms；系统关闭了动画效果时一律不播。

### 7.2 设计变量

| 变量 | 浅色 | 深色 |
|---|---|---|
| 看图背景 | `#F3F3F3` | `#1C1C1C` |
| 面板 / 工具栏 | `#FFFFFF` | `#2B2B2B` |
| 浮动工具栏 | `#FFFFFF`，不透明度 92% | `#2B2B2B`，不透明度 92% |
| 悬停 / 按下 | 叠加黑色 6% / 10% | 叠加白色 8% / 12% |
| 分隔线 | `#E5E5E5` | `#3A3A3A` |
| 主文字 / 次要文字 | `#1A1A1A` / `#616161` | `#F2F2F2` / `#A8A8A8` |
| 强调色（默认跟随系统） | `#0A6CFF`，按钮上白字 | `#4CA0FF`，按钮上黑字 |
| 危险（删除） | `#D13438` | `#FF6B6B` |
| 棋盘格 | `#FFFFFF` / `#E6E6E6` | `#3A3A3A` / `#2E2E2E` |

- 上表文字与其背景的对比度都满足 WCAG AA（≥ 4.5:1）。棋盘格每格 8 屏幕像素，不随缩放变化。
- 可点击的元素都有 悬停 / 按下 / 禁用 / 键盘焦点 四种状态；键盘焦点用 2 px 强调色描边。
- **字体**：启动时加载系统字体、不内嵌（中文字体内嵌要多 10 MB 以上）：Windows 用 Segoe UI Variable / Segoe UI + 微软雅黑 UI，macOS 用苹方，Linux 用 Noto Sans CJK。字号：说明 12、正文与菜单 14、标题 16、设置页大标题 20；数字用等宽数字（缩放比例、帧号变化时不抖动）。
- **间距**：4 的倍数（4 / 8 / 12 / 16 / 24）。
- **圆角**：按钮、输入框 4 px；菜单、面板、对话框 8 px；浮动工具栏 12 px。
- **尺寸**：图标按钮 32×32；浮动工具栏高 44、距窗口底边 16；编辑工具栏高 48、属性栏高 40、状态栏高 28；菜单项高 32。
- **动效时长**：淡入淡出 120 ms；工具栏、面板滑入 150 ms；缩放过渡 100 ms；鼠标静止 2 秒后浮动工具栏淡出。

| 场景 | 表现 |

| 加载中 | 有内嵌缩略图或低分辨率预览时先显示它，解码完成后无缝替换；超过 300 ms 还没有任何内容时，中央显示细小的加载环和文件名 |
| 打不开 | 中央显示图标 + 「无法打开此图片」+ 具体原因（格式不支持 / 文件已损坏 / 缺少系统解码扩展 / 没有访问权限 / 文件已被删除）+ 按钮「用其它程序打开」「在资源管理器中显示」；Windows 上缺 HEIC 扩展时给「去微软商店安装」；← → 照常切换 |
| 轻提示 | 底部居中的胶囊，2 秒后消失：「已复制」「已保存」「已移到回收站」「已回到第一张」「只有这一张图片」 |
| 确认框 | 只用在覆盖原图、彻底删除、放弃修改这类不可撤销的操作；按钮写清动作（「覆盖保存」「彻底删除」「不保存」），不用「确定」 |
| 文案 | 简短、动词开头、中文用全角标点；错误提示说清原因和怎么办 |

## 10. 技术方案（当前实现与后续计划）

- 语言：Rust（edition 2024），依赖锁定精确版本（与 AirPlay3 一致）。
- 界面：**egui / eframe**（跨平台即时模式 GUI，界面全部自绘）。扁平风格好调；看图 / 编辑器要在画布上画大量东西（圆圈光标、选框、控制点、浮动工具栏），用它最直接；自带输入法与读屏（AccessKit）支持。
- 分层：解码、编辑、打码、界面是跨平台的公共代码；文件关联、右键菜单、Windows 剪贴板格式、WIC 解码等放在按平台区分的模块里。

| 层 | 方案 |
|---|---|
| 窗口与渲染 | eframe（winit + wgpu）。M0 实测 wgpu 默认同时初始化 Vulkan、DX12、GL 时最重，所以按顺序只选一个：Vulkan → DX12（虚拟机里有 WARP 软件渲染）→ GL；macOS 用 Metal。Windows 上用 DWM 设置标题栏颜色 |
| 字体 | 启动时加载系统中文字体（见 7.2），不内嵌 |
| 大图 | 按显卡支持的单张纹理上限（一般 8192 ~ 16384）分块上传；缩小显示用 CPU 预先生成的多级缩小图（高质量、无摩尔纹），放大很多时用最近邻 |
| 解码 | `image`（JPEG / PNG / APNG / GIF / WebP / BMP / ICO / TIFF / TGA / DDS / QOI / PNM / HDR / EXR）、`resvg`（SVG）、`jxl-oxide`（JPEG XL）、`kamadak-exif`（EXIF）、自写 RAW 内嵌预览提取；系统解码器兜底：Windows WIC（HEIC、AVIF、RAW、JPEG XR 等）、macOS ImageIO（P2）。统一的解码器接口：按文件头选解码器，失败时依次回退 |
| 编辑 | CPU 端 RGBA 图像是唯一数据源（所见即所得、保存结果确定），改动区域增量上传到 GPU；画笔、形状抗锯齿用 `tiny-skia`；文字用 egui 文本框处理输入法、光标与换行，再用 `resvg` / 系统字体按相同布局绘制预览和写入像素（不是 `cosmic-text`） |
| 打码 | 马赛克、模糊自己实现；`rayon` 多线程，只算改动的分块 |
| 编码 | `image`（PNG / JPEG / BMP / TIFF / 无损 WebP）；GIF 用 `gif` + `color_quant` 并自实现误差扩散；JPEG 品质由标准量化表精确识别；EXIF 经 `kamadak-exif` 清理后交编码器重写。有损 WebP、各格式元数据能力补齐见 OPT-07 / OPT-10 |
| 系统集成 | 文件对话框 `rfd`；剪贴板 `arboard`（Windows 上自己写 PNG + DIBV5，保证透明图在微信、QQ 里能粘贴）；回收站 `trash`；目录监听 `notify`；单实例用本地套接字传路径；文件关联：Windows 写 HKCU 注册表、Linux 装 `.desktop`、macOS 写程序包的 Info.plist |
| 构建 | release：fat LTO、`codegen-units = 1`、strip；**不用** `panic = "abort"`（要用 `catch_unwind` 把单张图的解码错误挡住）；Windows 版嵌入图标、清单（每显示器 DPI v2、长路径）、版本信息 |
| 发布 | 严格 CI 覆盖 Windows / Linux / macOS；发布矩阵覆盖 Windows x64、Linux x64、macOS arm64 / x64，全部成功才可发布。已有 Windows 绿色 ZIP / 当前用户安装包、Linux tar.gz、macOS `.app` 归档；AppImage 未实现。手动工作流只产 artifacts，匹配应用版本的 tag 才创建 Release；本轮尚未发正式版 |
| 许可 | MIT；依赖只用宽松许可（MIT / Apache-2.0 / BSD / ISC / Zlib 等），不用 GPL / LGPL；发布包附第三方许可声明 |

- 已核实：`image` 0.25.10 的 `avif` 功能只能**编码**（ravif），解码要另开 `avif-native`（dav1d，C 库，Windows 上构建麻烦），所以 AVIF 在 Windows 上先走 WIC，自带解码器（各平台都能看）在 M0 评估；JPEG 解码用 zune-jpeg；WebP 编码只有无损。
- 代价：比纯 Win32 原生程序体积大一些、启动和空闲内存高一些（第 9 节已按此放宽，M0 实测后定）；换来一套代码跑三个平台。备选：iced、Slint（Slint 免费使用要求署名，或改用 GPL）。

## 12. 验收

- **性能**：自动化脚本在参考机上测冷启动、切图、内存，每个版本记录结果，对照第 9 节。
- **格式**：维护一套测试图（各种位深、灰度、CMYK、EXIF 的 8 种方向、透明、GIF 各种处置方式与局部帧、APNG / WebP 动画、损坏文件、解压炸弹）：要么正确显示，要么给出正确的错误提示，都不崩溃。
- **动图**：与 Chrome / Edge 逐帧对比，合成结果逐像素一致，帧时长误差 ≤ 10 ms。
- **打码安全**：覆盖保存后用十六进制查看与 aCropalypse 检测工具确认文件尾部没有残留；打过码的 JPEG 不含 EXIF 缩略图与 GPS；单元测试覆盖马赛克网格对齐（多笔、框选与画笔混用结果一致）与「同一笔不越涂越重」。
- **编辑**：6.7.2 每项都有手动测试用例；撤销到底后与原图逐像素一致（自动测试）。
- **文件关联**：在干净的 Win10、Win11 虚拟机上走一遍 注册 → 在系统中设为默认 → 双击打开 → 在系统中选择替代应用 → 移除注册；确认自身注册清理、其他应用注册和用户配置保留。程序不能写 UserChoice，也不能把移除注册描述为恢复旧默认应用。
- **每个版本**：GitHub Actions 在 Windows / Linux / macOS 上编译、单元测试全部通过；release 构建无警告；提交并推送 GitHub；发布 Release（附 Windows 绿色版）。

### 15.2 优化清单（按风险与价值排序）

#### OPT-01 · 解码资源预算贯穿所有入口 — P0，稳定性门禁

- **代码证据**：`src/decode/mod.rs` 的 `decode_file` 先整文件读取；`max_alloc` 在 `raster.rs` 使用，但 WIC / PSD / JXL / 动图的部分路径只做尺寸或帧缓存检查，未统一执行此预算；静态解码失败后还可能回退 WIC。当前有尺寸保护，不是完全没有防护；问题是“单张最多 4 GB”的承诺尚未覆盖所有路径与中间副本。
- **需求**：拆分源文件读取、解码像素/临时缓冲、帧缓存和并行预读预算；所有入口及回退都携带同一限制，限制拒绝不能经回退绕过。先查头/估算再分配，检查乘加溢出，支持协作取消；解码器无法可靠限额时明确降级/拒绝策略。`catch_unwind` 不作为内存耗尽防护。
- **验收**：用小预算覆盖静态图、动图、PSD、JXL、WIC 和回退路径，超预算时返回可读错误、不触发大分配；恶意尺寸/截断/高压缩比样本在受限测试进程中退出可控，随后仍可打开正常图。补 fuzz 入口与每次发现问题的固定回归样本（fuzz 属 P1）。

#### OPT-02 · 安装与发布可追溯性 — P1，发布门禁

- **代码证据**：`packaging/windows.iss` 已有注册所有权检查；`packaging/test_windows_installer.ps1` 已接入一次性 Windows runner，包含安装、合成 0.0.0 升级、卸载及绿色版接管场景。`src/app/mod.rs` 的 `--register` 失败目前仅记日志后返回成功，安装方不能仅凭退出码判断结果。
- **需求**：完成进程树等待修复后的生命周期 CI 重跑（本机回归与完整安装验收分别记录）；注册命令返回真实失败状态并提供可定位诊断。补真实旧版本迁移、交互式向导、Win10/Win11 默认应用流程；合成版本升级只证明安装流程，不证明应用数据迁移。
- **验收**：同一候选提交全部测试/包成功；异常注册非零退出；卸载不误删其他路径的关联，不删用户图片/配置；日志、二进制、许可证、校验值均能追到同一版本。无证书时明确“未签名”，不得以旧包替代新包或跳过失败平台。

#### OPT-03 · HEIC / AVIF 系统解码实证 — P1，格式验收

- **代码证据**：`src/decode/wic.rs` 当前返回 `exif: None, icc: None`，没有显式方向处理；尚缺真实 HEIC 方向样本及缺扩展机器的商店按钮实测，不能只靠“能编译/能提示缺扩展”声称完成。
- **需求**：在隔离 Windows 环境覆盖已装/未装扩展、实际设备照片、方向、元数据；先确认 WIC 已施加的变换，再处理剩余方向，避免二次旋转；分别呈现缺扩展、损坏、资源超限错误。
- **验收**：已知方向与参考渲染一致（包括会交换宽高的情况）；无法解码有正确原因；商店按钮打开预期产品、不自动购买；有代表性的已装环境样本进入回归，未覆盖组合明确列出。

#### OPT-04 · 性能测量与空闲内存 — P1，80 MiB 为优化目标

- **代码证据**：本机 92 MiB 满足当前 ≤100 MiB 空闲门槛，但不是参考机验收。`src/gpu.rs` 先建探测 Instance 再由 eframe 创建渲染实例，`src/ui/fonts.rs` 启动映射候选字体；两者只列为**待测假设**，没有证据把主要占用归给驱动。`src/platform/mod.rs` 的 macOS 内存返回 0、Linux 页大小写死 4096，也会影响比较。
- **需求**：先统一口径和可重复基线，再做 GPU 初始化复用、字体按需映射/去重等对照实验；冷/暖启动分开，记录硬件、后端、分辨率/DPI、提交、预读设置及 P50/P95。Windows 专用工作集、总工作集、提交量与 GPU 占用分列；Linux 使用运行时页大小，macOS 提供有效指标，不可用时显示不可用而非 0。
- **验收**：同场景多次测试可复核，参考机达到第 9 节门槛；80 MiB 单独记录是否达到，不靠降低中文字体覆盖、移除无障碍或破坏软件渲染兜底换数值。测量换算用 MiB（1024² B），与原表 MB 标签的历史口径说明一并保留。

#### OPT-05 · 长动图回退延迟与峰值内存 — P1，性能优化

- **代码证据**：`src/viewer/animation.rs` 已限制为一个 worker、最新请求与结果槽，顺播可复用解码器；回退/循环从头重建合成状态。`extra.rs` 的 JXL 路径先读取 keyframe 结构，输出缓存限额不等于解码器内部参考帧限额；首次建完整时间轴也需单独测耗时。
- **需求**：保持现有正确性前提下，评估受预算约束的邻近帧缓存、可恢复检查点与更早取消；不要未经测量就扩大常驻缓存。设置说明区分缓存、源数据、工作帧、解码器和 GPU；单帧大于缓存时明确最低必要工作集和超限策略。
- **验收**：覆盖 1 / 16 / 256 MiB 缓存、多尺寸长 GIF/APNG/WebP/JXL；记录首帧、冷跳末帧、连续后退、循环、导出和切走取消的 P50/P95/峰值。至少 10 轮播放/切图后无持续上涨或遗留 worker；缓存/按需像素与帧号一致。回退耗时先基线再定量化目标，不凭本机小样本宣称任意长图 60 fps。

#### OPT-06 · SVG 缩放重新栅格化 — P1，已有需求差距

- **代码证据**：`src/decode/extra.rs::svg` 固定长边 2048 px，当前查看器拿到的是位图，未达到 6.4 的“任意放大都清晰”。
- **需求**：保留受限的矢量源/解析树，根据缩放、视口与 DPI 后台重绘；重绘去抖和取消、只应用最新请求，沿用安全像素预算；明确导出/进入编辑时的栅格化尺寸。
- **验收**：小图标、细线、中英文 SVG 在多档缩放与高 DPI 下与目标尺寸直接渲染结果对比；快速缩放不阻塞 UI、不显示过期请求，峰值受预算控制，现有位图路径不回退。

#### OPT-07 · 保存能力与编辑状态一致 — P1，正确性

- **代码证据**：`src/save.rs` 忽略部分元数据 setter 的错误，GIF/BMP 路径未传 ICC；`src/app/edit/save.rs::edit_saved` 更新格式/EXIF/JPEG 品质但不更新 `icc` / `has_alpha`，且读回失败会静默使用内存图。这里是需要测试确定的状态语义风险，不能直接认定已发生隐私泄露。
- **需求**：定义每种输出格式的 EXIF、ICC、透明度能力和丢失提示；分清“正在编辑的画布”与“已保存文件”的色彩/透明度状态，避免简单替换画布破坏撤销。保存成功但校验读回失败应单独提示，不把回退图说成磁盘结果；补满盘、只读、文件占用与取消覆盖回归。
- **验收**：透明 PNG → JPEG → 继续编辑 → PNG、带 ICC/EXIF → 各格式、打码 → 保存/复制/撤销等矩阵均有明确预期；信息面板与读回文件一致；不承诺不支持的元数据保留，打码默认无缩略图/GPS，写入失败原图字节不变。

#### OPT-08 · Linux / macOS 与 Windows 兼容场景 — P1，原生验收

- **证据边界**：已有三个系统构建与四目标包，但未完成 Linux X11/Wayland、macOS Apple/Intel 原生打开、剪贴板、IME、拖放、默认应用、单实例等交互矩阵；Windows 参考核显、远程桌面与混合 DPI 仍需专门证据。
- **需求与验收**：在干净原生账户逐项记录安装/启动、中文路径、双击/拖入、透明剪贴板、编辑保存、中文输入、退出与桌面集成；Windows 补核显/软件后端/远程/多屏 DPI。每条附系统版本、构建、步骤、预期和结果；构建成功不得代替该清单。

#### OPT-09 · 纯键盘与读屏流程 — P1，无障碍门禁

- **代码证据**：`src/ui/widgets.rs` 已给图标按钮等填入语义；自动对比度测试与 AccessKit 接入不是 Narrator / VoiceOver 实际可用的证明。
- **需求与验收**：无鼠标完成打开 → 缩放 → 编辑/打码参数 → 撤销 → 保存/取消，补画布定位操作的键盘替代；验证焦点顺序、可见焦点、弹窗焦点恢复、选中/禁用状态与中英文读名。若画笔类操作不能键盘完成，必须记录缺口，不能写“全部操作已支持”。

#### OPT-10 · 有损 WebP 导出 — P1，已有需求差距

- **代码证据**：`src/save.rs` 当前只使用 `WebPEncoder::new_lossless`；6.4 / 6.9 的有损 WebP 与品质选择尚未兑现。
- **需求与验收**：先评估编码库的跨平台构建、许可、包体和延迟，再提供明确的无损/有损选择。无损回读逐像素一致；有损品质设置确实传入编码器，并用固定样本验证透明度、解码兼容性与质量/体积变化；没有实现前不展示无效质量控制。

#### OPT-11 · 色彩管理闭环 — P2

- **代码证据**：普通位图路径读取 ICC，但没有统一的 ICC → sRGB 显示转换；WIC 尚未返回 ICC，而 JXL 已请求 sRGB。保留配置文件与正确显示颜色是两回事。
- **需求与验收**：统一说明各解码器输出像素的色彩空间，使用带 sRGB/Display P3/Adobe RGB/CMYK 配置的固定样本与参考渲染核对；转换像素后匹配输出 ICC，避免附回旧配置造成二次转换；编辑、预览、保存色彩一致。实现前继续标明 P2，不承诺全流程色准。

#### OPT-12 · 后续格式与交付增强 — P2，不扩张 v1 范围

- **需求**：按现有 6.3 / 6.4 排期 macOS ImageIO、动态 AVIF、多页 TIFF、ICO 尺寸切换；Linux AppImage 作为现有 tar.gz 之外的可选包装，不替代已经工作的包。代码签名/公证须先确认凭据与费用，未授权不执行。
- **验收**：每项分别有真实样本、跨平台支持表与错误降级；不能因为已有格式嗅探或系统组件就标“已支持”。继续不做图库、云同步、遥测、自动更新与动图编辑。

#### OPT-13 · CI 成本与工具链可重复性 — P2，工程效率

- **代码证据**：CI 采用 stable + `--locked`，但未单独验证 `Cargo.toml` 声明的 Rust 1.95；工作流尚无 Rust 构建缓存。
- **需求与验收**：增加声明最低工具链的验证，若不兼容则修实现或准确更新要求；按 OS/架构/工具链/锁文件隔离缓存，比较冷/暖耗时。可缓存加速但不删 Clippy、测试、许可证或发布矩阵门禁，避免不可信构建写入发布产物。

### 15.3 建议执行顺序

1. **先守住正确性与发布证据**：OPT-01 → 最新安装生命周期结果及 OPT-02 → OPT-03 / OPT-07。
2. **再测量后优化**：先 OPT-04 基线，再做 OPT-05 / OPT-06；每个实验都附收益和回归，收益不足则不合入。
3. **完成 v1 原生体验门禁**：OPT-08 / OPT-09 / OPT-10；未验证项继续显式保留，不能以 CI 绿色宣告 v1 完工。
4. **P2 单独排期**：OPT-11～OPT-13，不阻塞已有预览版正常迭代，也不把未实现功能写进 README 成果。

- **OPT-01 部分落地**：源文件单独限为 512 MiB，读取前检查长度并限制实际读取；`max_alloc` 检查已贯穿普通位图、动图与按需帧、PSD、SVG 输出栅格、JXL、WIC，以及金字塔输出。超限不再尝试系统回退；JXL 给内部网格分配器一半预算，输出/帧缓存保留余量。PSD 通道数和 PackBits 截断检查补齐。小预算回归曾在旧代码的 PNG/WIC 回退、APNG、SVG 路径实际失败。**仍不是进程内存硬限制**：源数据、缓存、GUI/GPU、并行预读另计；WIC 没有分配器限额 API，SVG 解析/滤镜和部分第三方解码器也没有可靠硬限额。本轮没有完成进程级隔离、并发总预算或全解码协作取消，不能关闭整个 OPT-01。
